BASICS

What Is Screen Refresh Rate?

Three related measurements describe how a display and rendering system present motion. They connect, but they are not interchangeable.

01 / Display

Refresh rate · Hz

Refresh rate describes how often a display can update its image each second. A higher rate can make motion appear smoother and can reduce the time between scanouts, when the system and content can use it.

60 Hz ≈ 16.67 ms120 Hz ≈ 8.33 ms144 Hz ≈ 6.94 ms240 Hz ≈ 4.17 ms
02 / Rendering

Frame rate · FPS

FPS counts the frames a rendering system produces or presents per second. Browser animation callbacks are commonly synchronized with a display pipeline, but results depend on the browser, operating system, GPU, power mode, display configuration, and variable refresh behavior. FPS does not always equal monitor refresh rate.

03 / Timing

Frame time · ms

Frame time is the interval between frames. At 60 FPS, an average frame takes about 16.67 ms; at 120 FPS, 8.33 ms. Consistent timing matters: uneven intervals can make motion feel less smooth even when the average FPS looks unchanged.

METHOD NOTE RefreshTest estimates browser frame cadence from animation callback timestamps. It does not query the panel’s exact hardware refresh rate or measure pixel response time.

TEST PROCEDURE

How to Test Refresh Rate

01

Confirm system settings

Check the selected refresh rate in your operating system first.

  • Windows: Settings → System → Display → Advanced display
  • macOS: System Settings → Displays
02

Run the browser test

Keep this tab active and compare the measured browser cadence with your configured display mode. If it seems low, check hardware acceleration, power settings, GPU/display configuration, and heavy background apps.

03

Verify motion

Use the motion strip to inspect a moving shape at different speeds. It demonstrates motion smoothness only; professional panel tests are needed for response time, persistence, and artifacts.

REFERENCE

Refresh Rate Standards Explained

Useful ranges depend on the task, the content, and whether the system can sustain the matching frame rate.

60 HzStandard

Common for general computing, office work, and many video workflows.

120 / 144 HzHigh refresh

Noticeably smoother desktop motion and a common step up for gaming.

165 HzHigh refresh · gaming

More frequent updates for responsive play when the system can deliver frames.

240 HzCompetitive high refresh

Useful for fast interactive content; benefits diminish as rates rise.

360 Hz+Extreme competitive

A specialized option where frame delivery, latency, and player preference align.

VRRVariable refresh rate

Allows compatible displays to vary update timing within a supported range to better follow frame delivery.

06

USE CASES

Refresh Rate Needs by Use Case

Office & web

60 Hz is adequate for many tasks; higher rates can make scrolling and pointer motion feel smoother.

Gaming

Higher refresh can improve motion clarity and responsiveness. GPU performance, in-game FPS, response time, and VRR also matter.

Competitive gaming

High refresh may help expose more frequent updates, if the game and hardware sustain them. It is not a requirement for every player or title.

Video & film

Content frame rate and cadence often matter more than maximizing display Hz; compatible refresh modes can reduce judder.

Content creation

A stable, color-appropriate display may matter more than peak refresh for many workflows; higher Hz can still improve interface motion.

Mobile devices

Higher refresh can smooth scrolling, while adaptive modes may reduce power use when fast updates are unnecessary.

07

CONFIGURATION

Ensuring High Refresh Rate Is Active

The configured mode is limited by the capabilities of the whole display chain.

System settings

Choose the intended mode in Windows Advanced display or macOS Displays settings.

Cable & connection

Maximum resolution and refresh depend on connector versions, display and GPU capabilities, cable bandwidth, and compression support where applicable.

Browser acceleration

Hardware acceleration can affect rendering and callback cadence. Compare settings only after restarting the browser.

GPU settings

Review NVIDIA, AMD, or Intel display configuration and ensure the intended monitor and mode are selected.

Laptop power mode

Power-saving modes may change performance or display behavior. Test while plugged in if appropriate.

VRR configuration

Confirm variable refresh is supported and enabled in the display, operating system, GPU driver, and application path.

Refresh Rate Setup Tips

  • Windows / macOS: verify the selected mode in Advanced display or System Settings → Displays.
  • GPU: check NVIDIA, AMD, or Intel display settings.
  • Browser: review hardware acceleration, then restart the browser after changing it.
  • Power: avoid aggressive power-saving modes during comparison.
  • Verification: keep the tab active and close heavy background workloads.

QUESTIONS

Frequently Asked Questions

Why does it show 60 Hz when my screen is 144 Hz?

The browser may be receiving callbacks at 60 Hz because of system display settings, a display path limitation, browser/GPU configuration, power mode, or compositing behavior. Verify the active mode in system settings and keep the page in the foreground.

Is the browser measurement accurate?

It measures intervals between browser animation callbacks, which are often synchronized to the display pipeline. It is useful for checking browser cadence, but it is not a direct hardware measurement and can differ from the panel’s configured refresh rate.

Why are there spikes in the frame-time chart?

A spike means one callback arrived later than nearby callbacks. Heavy CPU/GPU work, background activity, compositing, power management, or a missed presentation opportunity can cause it. Very large gaps are excluded from the cadence estimate and reported separately.

What is the difference between Hz and FPS?

Hz describes display update frequency. FPS describes frame production or presentation rate. Browser rendering is commonly synchronized with the display pipeline, but the two values do not always match.

What is frame time?

Frame time is the time between frames, measured in milliseconds. Consistent frame times usually produce steadier motion than irregular timing with the same average FPS.

Why can my refresh rate change?

Operating-system modes, VRR, battery settings, display connections, GPU load, browser behavior, and whether the page is visible can all affect callback cadence.

What is VRR?

Variable Refresh Rate lets a compatible display adjust its update timing to follow frame delivery within a supported operating range. Exact behavior depends on the display, GPU, software, and configuration.

Does higher refresh rate reduce input latency?

It can reduce the time between display updates, but total input latency also depends on input polling, game/application processing, frame queues, GPU load, scanout, and pixel response.

Can this test measure monitor response time?

No. Browser animation cannot measure pixel transitions, GtG, MPRT, or panel response time. Those require dedicated measurement equipment and test patterns.

Can this test detect my monitor’s exact hardware refresh rate?

No. Browser APIs expose animation callback timing, not a guaranteed exact panel refresh rate or native resolution.

Why can two browsers produce different results?

Browsers can use different compositors, GPU paths, scheduling policies, and power behavior, even on the same system and display.

Why does the result change when I move the browser window?

Moving a window between displays or changing its visibility can change which display pipeline, refresh mode, or compositor behavior drives its callbacks.
